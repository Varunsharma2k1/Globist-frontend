# India map asset

`src/features/indiaMap/data/indiaMap.json` (~260 KB) is generated by `build.mjs` from
Datameet's state boundaries. They follow Survey of India and include all of Jammu & Kashmir,
Ladakh and Arunachal Pradesh. You only need to rerun this if you change the source data or the
simplification.

## Regenerate

```bash
cd mobile
mkdir -p /tmp/datameet && cd /tmp/datameet
for e in shp shx dbf prj cpg; do
  curl -sLO "https://raw.githubusercontent.com/datameet/maps/master/States/Admin2.$e"
done
cd -
node scripts/india-map/build.mjs /tmp/datameet/Admin2.shp
```

`mapshaper` and `d3-geo` are devDependencies, used only by this script. The app never uses them.

## What the script does

1. **Simplifies** the 17 MB shapefile with mapshaper (`-simplify percentage=2% weighted keep-shapes`).
   `keep-shapes` keeps small islands and UTs (Lakshadweep, Andaman, Chandigarh) from disappearing.
   Don't add `-clean`: it rebuilds shapes from the unsimplified borders and undoes the simplification.
2. **Fixes ring direction** so d3 doesn't read a state as "the whole world minus the state".
3. **Projects** with a Mercator fitted to India's width (`MAP_WIDTH = 1000` map units) and turns
   each state into an SVG path string (1 decimal place, repeated points removed).
4. **Checks** that the app's runtime projection (`src/features/indiaMap/geo/mapGeometry.js → project()`)
   gives the same numbers as d3, so pins line up with the borders.
5. Writes `{ width, height, projection, states: [{ id, name, d, cx, cy, bbox }] }`.

| Tunable | Default | Effect |
|---|---|---|
| `SIMPLIFY` | `2%` | Higher = more border detail and a bigger file |
| `DIGITS` | `1` | Coordinate decimals |
| `MAP_WIDTH` | `1000` | Size of the map space (only changes the numbers, not how it looks) |

State ids (`HP`, `UK`, `GA`, …) come from the `IDS` table in `build.mjs`, and pins refer to these.
